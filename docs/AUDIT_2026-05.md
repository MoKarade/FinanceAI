## Note exécutive

FinanceAI est **techniquement ambitieux et globalement sain** mais souffre de **dette accumulée** sur des zones critiques. Le moteur de projection a été superbement modularisé (cycles 1-29) mais **la qualité fiscale, la sécurité applicative et l'architecture frontend** présentent des écarts sérieux avec la promesse "qualité production".

**Score global pondéré : 5.6/10** — fonctionnel et refactorable, mais **pas prêt comme outil de conseil fiscal réel** sans corrections.

**3 verdicts qui doivent guider la suite :**

1. **La fiscalité 2026 est dépassée ou incomplète** sur 22 points distincts. Sur les 10 claims initiaux, **2 audits indépendants ont confirmé 10/10**. Les paliers fédéraux et québécois utilisent une indexation 2024-2025. La bonification PSV 75+ est totalement absente. Le prorata RRQ est cassé pour tout immigrant (rend RRQ = 0$).
2. **3 vulnérabilités sécurité HAUTES** : XSS via `dangerouslySetInnerHTML`, export non chiffré qui inclut les clés API, passphrase backup à 8 chars (faible pour AES-256-GCM brute-force hors-ligne).
3. **State versioning absent** : aucun `version`/`migrate` dans le `persist` Zustand. Toute évolution future du schéma cassera le boot des utilisateurs existants.

## Forces du projet (à préserver)

- **Modularisation moteur projection** : 31 modules `services/projection/`, 148 tests intégration solides
- **Cryptographie backup** : AES-256-GCM + PBKDF2 600 000 itérations (gold standard)
- **CSP stricte** Netlify, SSRF mitigé via SHEET_ID hardcodé
- **Zod sur réponses Gemini** : validation stricte, anti prompt injection partielle
- **`ErrorBoundary` par tab** avec `resetKey={activeTab}` (pattern exemplaire)
- **`AbortController`** pour syncs Era Context concurrentes
- **`runAsync.ts`** : pattern requestId + timeout 30s + cleanup propre (modèle à dupliquer)
- **Lazy loading systématique** des 17 onglets avec Suspense
- **Scripts `verify-precision.ts` + `diff-snapshots.ts`** : SHA-256 baseline pour valider refactor
- **Migration localStorage** avec backup automatique en cas de corruption
- **`partialize`** exclut `apiKeys` de la persistance Zustand (mais reste dans export JSON, voir S2)
- **PRNG seedé** (`buildSeededRng`) pour Monte Carlo déterministe
- **`runAsync` Web Worker** dédié avec timeout, abort, garbage collection
- **i18n setup** (i18next + react-i18next) prêt à étendre
- **PRE (résidence principale)** correctement modélisée par omission dans estate calc
- **SCEE (CESG) 20% + IQEE 10%** correctement implémentés
- **RAP 60 000$ + délai grâce 5 ans** correct
