## Verdict global

Le **cœur money-critical est sain** (l'audit financier 2026-06-17 l'a prouvé AAA, conservation ≤ 0,02 $).
Les deux « bugs de chiffres » rapportés par l'audit UX ne sont **pas** des erreurs de calcul :
- **Budget « diffère »** = il affiche le patrimoine **successoral** (`estateNetWorth`, net d'impôt au décès +
  NPV rentes), pas le patrimoine de fin d'horizon. Source unique RESPECTÉE → problème de **libellé**.
- **Patrimoine négatif** (Karim −1,88 M$) = persona **volontairement insoutenable** (retraite à 50 ans,
  capital modeste, train de vie indexé 45 ans) ; le NW négatif est de la **dette liquide VISIBLE**, le moteur
  conserve l'argent. → problème de **présentation** (anxiogène sans contexte d'insolvabilité).

Les vrais problèmes actionnables sont : (1) **formatage monétaire** contourné (75 sites), (2) **architecture
de l'information dispersée** (14 destinations, contenus/scores/holdings dupliqués), (3) **mode discret** qui
ne masque pas la valeur, (4) polish onboarding/gate/viz.

## 1. Money-critical

### FMT-CURRENCY-UNIFY — ✅ VÉRIDIQUE (MOYEN, présentation)
Les KPI principaux (`DualKPIStat` → `formatCAD`) sont corrects, mais **75 occurrences** de formatage `$`
manuel sur **12 fichiers** contournent le helper canonique `formatCAD` (`utils/format.ts:41`). Deux
pathologies : `toLocaleString()` **sans locale** (hérite du runtime → `164,400` en-US au lieu de `164 400`
fr-CA) et `.toFixed(n)` / divisions brutes (→ `746.667$`, `1100$` sans séparateur). Pire cas page **Impôts**
(`TaxCenter.tsx` l.254-436), **Budget** (`BudgetGroupTable.tsx:186` `displayTarget` = `target/12` non
arrondi), **Dettes** (`DebtManager.tsx` : `37,000 $` l.81 vs `1100$` l.103 **sur la même page**).
Pas une erreur de calcul (valeurs justes) mais **brise la confiance** (lecture d'ordre de grandeur).
→ Router chaque site par `formatCAD()`. Sites : `TaxCenter` 254/258/262/266/319/330/340/343/376/381/394/413/418/431/436,
`Budget` 484/777/780/808/811/819/851, `BudgetGroupTable` 78/80/117/122/124/126/186/197/215/244,
`DebtManager` 81/103/104/120/122/139/140/150 (+ `Retirement`, `LifeEvents`, `Investments`, `Planning`,
`AiAssistant`, `DividendPanel`, `Transactions`, `Travel` pour la campagne complète).

### PROJ-BUDGET-PARITY — ◑ PARTIEL (libellé, pas calcul)
L'écart Budget vs Accueil/Invest/Retraite est réel et reproductible, **mais la source unique est respectée** :
les 4 surfaces lisent `lastProjection`. Budget affiche `estateNetWorth` (`Budget.tsx:446`, libellé
« Patrimoine **successoral** projeté » `:649`) = `finalRawNetWorth − impôt successoral + (NPV RRQ/PSV)×0.7`
(`estateCalculation.ts:195`), tandis que les autres affichent `chartData[dernier].NetWorth`. Le **signe** de
l'écart prédit par la formule colle exactement aux 4 personas de l'audit. → **Décision produit** : aligner les
libellés (soit Budget montre aussi le NW fin-horizon, soit clarifier « successoral » vs « fin d'horizon »
partout). PAS un correctif moteur. ≠ `NW-PARITY-INVARIANT` (qui vise le NW présent).

### PROJ-NEG-SINGLE — ✗ FAUX (pas un bug) → item UX
Karim (−1,88 M$) prend sa retraite à **50 ans** (`karimImmigre.ts:82`) avec ~742 k$ de capital et ~8 250 $/mo
indexé sur ~45 ans : déficit structurel financé, après épuisement des comptes, par `liquidDebt` **VISIBLE**
(FISC-BROKE-LIQUID-FLOOR, `projection.ts:1278`). NW = `−liquidDebt` exactement, **sans intérêt usuraire**,
reconstructible, conservatif. Le moteur est correct — c'est le **signal** attendu (« plan insoutenable »).
Mais afficher « −1,88 M$ » sans contexte est anxiogène/trompeur. → **Item UX** : badge « plan insoutenable /
capital épuisé à l'âge X » quand `shortfallRate > seuil` ou NW franchit 0.

## 3. Vie privée & sécurité

### PRIV-DISCRET-DOM — ✅ VRAI (MEDIUM) ⚠️ recoupe [D6-SR-2]
Le « mode discret » = `filter: blur(8px)` CSS (`Layout.tsx:183-208`) : la **vraie valeur reste en clair dans
le DOM** (copier-coller, inspecteur, désactivation de classe l'exposent). **Pire** : `.privacy-blur:hover {
filter: blur(0) }` → un simple survol **révèle** le montant. La migration `PrivateAmount`/`PrivateBlock`
(`aria-hidden` + `sr-only`) corrige la fuite **lecteur d'écran** des sites migrés mais la valeur reste dans le
DOM. → Masquer la **valeur** (`•••`), pas la flouter ; retirer le hover-to-reveal. Recoupe la campagne
`[D6-SR-2]` (≈69 `privacy-blur` à migrer) — angle NOUVEAU = remplacement de valeur + hover.

### SEC-CSP-HEADER — ◑ PARTIEL (FAIBLE, cosmétique)
`index.html:34` a un `<meta http-equiv="Content-Security-Policy">` avec `frame-ancestors` — **ignoré en meta**
par spec (warning console). MAIS `vercel.json:10-11` livre déjà une CSP HTTP **+ `X-Frame-Options: DENY`** :
la protection anti-clickjacking est **bien active**. → Retirer le `frame-ancestors` inutile de la meta (tue le
warning console). Pas une faille.

### NAV-IA-ROUTE — ✗ FAUX (perception)
Le routage « Assistant IA » fonctionne (`TabRouter.tsx:277-291`). L'auditeur a heurté `PageSetupGate` (profil
non configuré → reste sur setup). Comportement de garde, pas un bug. → Perception : la gate de setup peut
sembler « page cassée » ; envisager un message « configure ton profil pour débloquer l'Assistant ».
